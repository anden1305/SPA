Special Course - Project framing

Towards subject-invariant and temporally coherent end-to-end latent models for unsupervised mouse sleep staging

Main aim
Build an end-to-end version of your thesis pipeline that:

replaces FFT-based inputs with CNN feature learning

keeps conditioning only in the decoder

replaces the static GM prior with a temporally dependent latent prior

tests zero-shot transfer from decoder-only conditioning

ends in a 5–10 page paper draft

Core research question

Can an end-to-end convolutional autoencoding model with decoder-only conditioning and a temporally dependent latent prior learn a more transferable and subject-invariant latent space for unsupervised mouse sleep staging than the FFT-based cGMVAE pipeline?

The right structure: 3 layers

Layer 1 — Invariance

Remove subject conditioning from encoder

Keep subject conditioning only in decoder

Test true zero-shot on unseen mice without using held-out subject data during representation training

Lab conditioning: Use Lab 5 (E) first

has the same montages (1 parietal + 1 frontal electrode )

this has 5s epchs but has been fixed by Javi to 4s

Montage conditioning: Then use lab 2 (B)

has double the channels but same montage placement (2 parietal + 2 frontal electrodes)

was 1s epochs but has been fixed by Javi to 4s

Ignore lab 1 and 4 as they are not as good.

This directly targets the issue that the thesis cGMVAE population result was partially transductive because the subject-conditioned encoder used limited held-out-subject data.

Layer 2 — Representation

Replace FFT / expert spectral frontend with CNN encoder

Use transposed convolutions in decoder

Train on consecutive windows or epoch windows from raw time-domain input

Compare against thesis spectral baseline

This is well motivated because the thesis explicitly proposes incorporating time-domain inputs and possibly staged spectral-to-end-to-end training.

Layer 3 — Temporal prior

Replace static GM prior with latent temporal prior

Since you want “HMM mixture prior i det latente rum” + “time dependency”, the clean interpretation is:

mixture structure in latent space

temporal dependency across latent states

practically: first implement a simple autoregressive Gaussian-mixture latent prior, then connect to HMM-style state interpretation if possible

This follows the thesis future-work direction to replace the static mixture prior with an autoregressive latent prior.

Preditions

MARHMM predictions (self.model.predict()):

Encodes input to latent space via CVAE

Runs MARHMM inference (uses learned transitions, lags, temporal state dependencies)

Returns: temporally coherent state predictions

What it tests: "Can MARHMM learn temporal structure on this latent space?"

GMM prior predictions (self.model.predict_gmm()):

Encodes input to latent space via CVAE

Runs GMM inference (static clustering, no temporal structure)

Returns: cluster assignments directly from the learned Gaussian mixture

What it tests: "Can the GMM prior alone (without MARHMM) cluster the latent space?"

Why training across labs is hard

1. Different recordings, not just different mice
Labs differ in montage (lab_2: two parietal EEGs; lab_3/5: parietal + frontal), scoring, and amplitude. The audit showed lab clusters in feature space stronger than stage clusters even after the same FFT pipeline. The model must learn “sleep stage” on top of that shift.

2. Decoder-only pushes identity into the decoder, not the latent
With decoder_only_conditioning: true, the encoder builds one latent space from mixed labs without being told which lab/mouse. The decoder is supposed to fix lab-specific reconstruction. That works well when train and test look similar (your thesis: mostly lab_3, subject scope). On joint 3-lab holdout, the encoder sees lab_2/5 mice it never saw at train time and must still produce latents the GMM can score as Wake/NREM/REM—that is a much harder generalization problem.

3. Holdout is harder than your thesis table
Thesis rows: subject or population, often same lab / similar setup, GMVAE trained on “all except the predictive split.”
cv4fold fold 4: train on 17 mice from 3 labs, test on 6 held-out mice from all 3 labs. That is real cross-site generalization, not “same lab, new night.”

4. Hyperparams were tuned for subject, not subject_lab
Bayes tune winners were picked with conditioning_source: subject and in-sample all-mice setup. Plugging in subject_lab without re-tuning gave NMI ≈ 0 (collapse). That is a mismatch, not proof that “lab + subject” is wrong in principle.

CONDITIONING

Your reported GMM/HMM NMI goes through encode → prior on z. The subject_ids argument is passed but ignored by the encoder in decoder-only mode. So at LODO test you do not get “random embedding poisons the latent” the way encoder-conditioned cGMVAE does.

That is why decoder-only is a better fit for population generalization than encoder+subject, and why your thesis’s 1/3 held-out leakage protocol is mainly an encoder-conditioning issue.

So for “new mouse, same lab” and your current metrics:

Decoder-only + subject_emb: latent staging can generalize without a trained row for the held-out mouse (encoder doesn’t look it up). Remaining gap is true distribution shift (spectra the encoder never saw), not bad embedding lookup.

Encoder + subject_emb: latent does use the embedding → held-out mouse needs leakage/few-shot or you get bad conditioning.

What is still true

Subject embedding is not a generalization mechanism for unseen mice.
It’s a per-mouse decoder knob for seen mice during training. It doesn’t give you a meaningful “identity vector” for a new mouse at test.

Training still uses subject_emb in the decoder for every training mouse (forward → decode(z, subject_ids)). The encoder is pushed to produce z that decodes well with mouse-specific decoder inputs — nuisance is meant to live in the decoder, not in z.

LODO is still hard — the held-out mouse’s EEG was never in training. Decoder-only removes the embedding artifact; it doesn’t remove spectral / cohort shift.

Lab conditioning still matters for decoder-only if you care about reconstruction or later add lab to the encoder. For labs 2/3/5 (different montages, 3 vs 4 stages), lab is the metadata you know at test time for a new mouse; subject ID is not.
